M5 exit report
==============

This report describes Oseo's measured M5 profile against the applicable
ECMA-262 16th edition inventory. It is not a claim of unqualified ECMA-262
conformance. [ADR 0016](../adr/0016-dynamic-source-boundary.md) is accepted
and keeps the dynamic source family outside the profile, and the
[ADR 0031](../adr/0031-m5-named-deferral.md) deferral list is not empty.
Under [ADR 0019](../adr/0019-m5-claim-closure.md) that label is a separate
later gate, which also requires an empty deferral list.

Every one of the 41,091 included inventory paths is reviewed. None is a
semantic, harness, or infrastructure failure. Each unsupported path is covered
either by an accepted record that authorizes and bounds an M5 exclusion or by
a named deferral, and no remediation node still owns a path. ADR 0031's
wording for this result is that measured residue was deferred by name and M5
closed. A deferred path is never reported here as passing, excluded, or
closed.


Measured profile
----------------

The claim is the edition and optional-section policy that
[ADR 0013](../adr/0013-m5-edition-and-manifest.md) fixes, measured against
the inventory that [ADR 0020](../adr/0020-m5-applicable-test-inventory.md)
classifies. The normative
[*M5 language profile*](../language-profile-m5.md) records the admitted
families and their evidence. This report counts results; it does not restate
that profile.

Percentages, where anyone publishes them, use the 41,091 included paths as
the denominator. Exclusions and deferrals are separate counts and never add to
the closed count.

Authorized exclusions
---------------------

Three accepted records own excluded paths. ADR 0019 supplies the rule that
lets an accepted record authorize an M5 exclusion, and owns none itself. The
[exclusion audit](./exclusion-audit.md) binds each excluded path to a review
of its pinned source and observation, and *exclusion-audit.yaml* quotes each
record's authorization and reopening text.

ADR 0016 owns the dynamic source paths: direct `eval`, the `Function`
constructor and the other source-compiling constructors, and dynamic
`import()`, each observed as the owned `OSEO1001` rejection. Where a path
also asserts something other than source evaluation, the audit names the
static or native evidence that observes it. The record is reopened by a
compatibility laboratory showing that target packages need `eval`,
`Function`, or unrestricted dynamic import; by a staged-compilation probe with
acceptable code lifetime, rooting, and target coverage; or by a WinterTC
profile that makes one of them a conformance requirement. ADR 0019 adds one
more trigger: evidence that a normative section inside the claim depends on
dynamic source for behavior other than source evaluation.

ADR 0013 owns the Annex B paths whose core subjects reviewed replacement
evidence fully observes, so that only the Annex B legacy behavior stays
unsupported. Evidence that a dependency inside the boundary requires an
excluded section reopens its optional-section policy.

[ADR 0028](../adr/0028-legacy-function-caller-boundary.md) owns exactly the
23 paths in its selector, which expect reading `caller` on a non-strict
ordinary function to complete normally. Target-package evidence that caller
introspection is needed, a bounded runtime design at acceptable cost, a later
edition that requires the behavior, or evidence that one of these paths mainly
tests a mandatory contract reopens it.


Named deferrals
---------------

Every deferred path is in the dynamic source area, and
[*PLAN-DYN.md*](../../PLAN-DYN.md) inherits all of them. Each entry in
[*deferrals.yaml*](./deferrals.yaml) gives its reason, the contract that
remains, the nodes and decisions that tried to close it, and digests of its
pinned source and observation.

The `run-time-source` family asserts contracts that are observable only
through run-time source compilation, such as a `var` declaration made by
direct `eval` or the `Function` constructor's own argument conversion. The
maintainer did not approve general `eval` or `Function` construction for M5,
and the evidence work found no static or host Script witness that reproduces
those observations.

The `static-specifier-import` family observes its contract only through an
`ImportCall` site, which the parse-time `OSEO1001` rejection blocks. Static
module evidence cannot witness repeated host loads, cached evaluation state,
deferred evaluation, or staggered graph starts. Its only route is the
build-time static-specifier import track, which the maintainer moved past M5.


What the audit checks
---------------------

`mise run check:m5-exit-audit` runs the closure ledger, exclusion audit, and
deferral validators over one reading of the reviewed manifest, then checks
that:

 -  the inventory, reviewed subset, manifest, ledger, exclusion audit, and
    deferral list name the same test262 revision;
 -  the reviewed subset and the manifest each cover every included path once,
    with matching classifications, and the ledger lists each included path
    exactly once;
 -  no path is a semantic, harness, or infrastructure failure or unreviewed;
 -  every unsupported path is owned by an accepted record that the exclusion
    audit reviews, with at least one reopening trigger, or by a deferral entry
    with a remaining contract and an inheriting target, and no path is owned
    by a remediation node or by nobody;
 -  the exclusion audit, deferral list, and ledger agree on the exclusion
    and deferral counts; and
 -  the coverage section of this report matches the regenerated text.

The existing validators already reject a stale record digest, a changed
source or observation digest, an exclusion outside its record's bounded
surface, and a deferral whose target is not a later milestone or a deferred
track.


Conditions outside the audit
----------------------------

Two exit conditions are outside what the repository can check. Both held
when the audit landed.

The audit could use the deferral list only after the maintainer received
the complete *deferrals.yaml* with a summary of its total path count,
per-family counts, each distinct reason with its count, and target
milestones, with every entry outside the dynamic source family flagged, and
raised no objection within the coordination wait period. The maintainer
received it on 2026-11-01, when it had 26 entries, and on
2026-11-02 with all 74 after the last remediation paths were assigned.
Every entry in both lists is in the dynamic source family. No objection
arrived within the coordination wait period.

`mise run check`, `mise run test`, and `mise run test:property:extended`
passed from a clean checkout of commit
`138f194c3571cb7c0026d7eff545c46dc0187c6f`, which merges the audit into the
last landed implementation. The landing commit adds only the graph state and
this text to that tree, and its candidate and main CI runs repeat the
ordinary and extended gates on the exact commit. These gates also carry the
semantic, property, sanitizer, and target exit criteria that
[*ROADMAP.md*](../../ROADMAP.md) lists for M5.
