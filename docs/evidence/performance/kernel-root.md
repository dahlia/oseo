Kernel comparison through direct Root boundaries
================================================

This private adapter prepares the Measurement checkpoint in
[*PLAN-PERF.md*](../../../PLAN-PERF.md). It connects the ordered kernel
comparison to direct Root allocation, an independent collector parent,
the existing profiler and the unchanged Source8 Python observer. Offline
fixtures exercise the contracts; they are not host admission or measurement
evidence. The actual accepted core/S deployment and end-to-end run remain
Root prerequisites.


Private entry and source boundary
---------------------------------

`runKernelRootOperator()` consumes a pinned direct Root allocation and the
existing manual operating channel. It verifies normal source inputs before
opening a collector window. `KernelRootOperator` writes private command
requests, consumes echoed original terminals, checks the command's exact
`argv`, environment and raw files, and constructs H proofs after those checks.
`produceKernelOperatorCommand()` is the corresponding fixed-command producer
for Root's already allocated native session. Explicit `native-parent`
transport executes the fixed commands as children of that same collector
parent. `manual-files` consumes originals from the allocated existing manual
channel; its additional processes need their original allocation evidence.
Neither transport opens SSH or grants privilege. There is no standalone
operating CLI or default success provider. Diagnosis consumes P's actual
original discovery and tool pins. Its `unverified` acceptance remains intact;
profile acceptance still requires each artifact's complete P replay.

The Root/manual side delivers each original terminal into the requested
owner-only file. The command record retains its original `stdout`, `stderr` and
JSON under a private directory. Requests bind sequence, task, host and `argv`.
Unknown terminal, channel loss, changed bytes or a mismatched echo blocks
further command dispatch and requires existing manual recovery. A digest
binds bytes; the direct Root allocation supplies authority.

`runKernelRootParent()` starts S with `local-read` in the supervising OS
parent. The unchanged generic supervisor owns *child.ts*, where synchronous
H and P execute. Private files carry H's eight ordered boundary phases.
Parent channel loss aborts the owned supervisor group; S remains independent
so it can observe terminal and restoration boundaries. Offline injection
seams use the actual H/S/supervisor types and grant no source admission.

The normal runtime path checks committed `HEAD`/tree, clean state, index flags
and allocated source pins before dynamic imports. The generic supervisor
entry is fixed to commit `ff355628258a65c9af55323673085c8115e2f556` and its
original entry hash. The current worktree lacks the pending H/S modules;
read-only contract checking against their actual source does not make them
accepted runtime dependencies. No unlanded implementation is copied here.


Kernel lifetime and process ownership
-------------------------------------

*lifetime.ts* implements a kernel allocation rather than constructing a demo
`RootDeployment` or importing the demo TypeScript consumer. It uses the
unchanged *demo-linux-lifetime.py* from normal Source8 commit
`e391e1d9a4e3ae8733076742440ea37f9705feb4`, tree
`ba87f0c85515b50e9d6b72f01520c26e7a052239`. The helper's SHA-256 digest is
`b6ae72f71a8b80a3aba440224a184b6f950fc5daed635873c89b5c3e78c5c77f`.
The parent verifies that normal component, the allocated interpreter and the
supervisor's inclusion of the lifetime dependencies. Python's real path,
bytes, mode, hash and complete version string are explicit inputs.

The control child starts the helper before its first `git`/`ps` subprocess.
Only its original anonymous `stdin`/`stdout` pipes carry the challenge and nonce
reply. The helper opens one persistent pidfd. Root checks the original
helper PID, socket device/inode/owner/mode through its allocated path and
proc-cwd path, then performs the private socket handshake. Python verifies
Root's kernel peer credentials. Subsequent S samples are pinned before a
causal post-poll with the same handle generation and increasing sequences.
The consumer replays the original pipe, Root arm, sample/probe pins and poll
transcript. A later arm does not apply to an earlier probe.

The live-session rule applies only to rows in that original live leader's
session group and owned UID. Original `stat` bytes must still identify the
same PID=PGID=SID leader and Root parent. Missing birth information,
incarnation data, and fork attribution remain unknown. Other vanished leaves
require a known, unchanged Root-anchored chain in both adjacent accepted
samples, with `stat` reads bracketing the original `ps`. An unknown
intermediate or a reused unknown leaf fails. The exact reaped S ps-self
exception also preserves its null birth.

Quiet checks admit the helper only while Root still holds its connection: at
each window close and before finalization. The admitted row must be the PID
that the replayed arm names, with the control leader as its parent,
process-group leader and session leader, the interpreter's file name as
`comm`, and one birth across every
sample whose `ps` started after the Root arm. Its descendants and any other
process are not admitted. Final cleanup admits no helper; it requires the
helper's reap and cleanup results and an inventory without it.

| Interval or process    | Evidence required for acceptance                                                                 | Failure boundary                                                                      |
| ---------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------- |
| Prearm/bootstrap       | Original known `stat` identities or a bracketed stable chain                                     | A later pidfd arm cannot repair a missing earlier birth.                              |
| P detached group       | Its known original identity/chain and separate terminal evidence                                 | The control leader's pidfd supplies no detached ownership.                            |
| Helper close           | Original close exchange, helper reap, terminal and each FD cleanup result                        | A close acknowledgement alone is insufficient.                                        |
| Postleader/restoration | Original known identities and quiet inventory, plus normal supervisor and operating records      | No live-session rule survives the leader or helper.                                   |
| Whole host             | Continuous Root ingress controls and original S observations for the complete requested interval | Sampling, a lease and successful subprocess cleanup alone do not establish exclusion. |

Interpreter pins cover the executable and declared version. Shared libraries,
standard-library files, Node.js `spawn()`/close-on-exec behavior, kernel and
loader configuration remain host runtime dependencies. The preparation inventory
records observed files without claiming a verified complete runtime. Actual
archives must retain allocated source/dependency files and original raw
transcripts, not just absolute locator paths. The observer adds work; no
zero-overhead claim is made. Same-UID descriptor theft is outside its pipe
ownership guarantee.


Original Mac transitions
------------------------

The operator records baseline, stop and restore events with their original
command sequence and UTC bounds. Each event carries the original `launchctl`,
plist and `ps` records. The reader replays them and records immutable listener
identities. Pending samples are judged against their own original times and
those transitions, rather than the consumer's current active flag.

Both UID 502 and UID 503 remain forbidden in every sample intersecting a
profile or timing window. Outside a window only the exact known listeners
are admitted. A transition can span a sample; any listener in that sample must
match an adjacent original state, including UID, parent, executable and
birth. An unknown birth, a partial `bootout` or an unknown command terminal
prevents a window from opening. A restored listener's later identity does not
exempt an unrelated earlier process.

The only service exception is mac-mini-m6, UID 501, with exactly
`system/org.oseo.runner.oseo-mac-1` and
`system/org.oseo.runner.oseo-mac-2` and their original
*/Library/LaunchDaemons/org.oseo.runner.oseo-mac-1.plist* and
*/Library/LaunchDaemons/org.oseo.runner.oseo-mac-2.plist*.
Original plist hash, mode, owner and identity are checked before actions and
restoration. Existing ingress evidence must show that active jobs, hooks and
children ended normally before stop. A known partial stop compensates only for
services confirmed absent. An unknown terminal or a failed restore blocks
further automatic commands and requires manual recovery. Listener state and
external Root acceptance remain required after restoration. The operator also
consumes the original existing GitHub runner response after the restore event
and checks that both runners match the exact names and are registered, online
and idle. Root supplies that original through its existing channel; the adapter
obtains no token or API permission. No other Mac gains service permissions.


Linux window and external acceptance
------------------------------------

The operator requests only the approved user-managed UUID window for the
same boot and canonical */sys/devices/virtual/dmi/id/product\_uuid* inode.
It checks the original device, inode, type, root owner/group and 0400
mode, then requests the exact approved 0444 command. After verifying the
same identity and 0444 mode, it starts S. Module loading, allocation validation
and private control setup precede the opening. The mode remains 0444 throughout
the actual collector lifetime.

The operator's direct commands request metadata, not the UUID contents. S and
the unchanged Source8 helper each read those contents through the
*/sys/class/dmi/id/product\_uuid* alias. S retains its copy in private raw
files; the helper returns its copy, or its read error, in the arm. Allocated
`KernelHost.hardware` also carries the UUID into `config.host` and
`binding.host`, independently of the helper's observation. The helper's `argv`
contains that configuration during its lifetime within the approved 0444
window.

Treat the entire private run evidence output as sensitive raw data, including
the lifetime directory, allocations, parent/child controls and retained
evidence. Exact UUID copies can occur through allocated host data,
configuration, bindings and the observed arm. For example, *lifetime.ts*
retains configuration in *spawn.json*, arm and binding data in pipe and Root
arm records, and bindings in poll and Root close records and their wire
strings. *child.json* and parent/child controls also carry host data or
`comparison.physicalHost`. This does not mean every individual record contains
a UUID. Keep these evidence directories owner-only 0700 and their files
owner-only 0600, retaining original bytes privately. These modes apply to the
private evidence, not executable benchmark artifacts or deployed source.
UUID contents must not appear in public output, general logs or outer review
evidence.

Reader termination and raw adjudication are separate. The parent retains S's
original finish record and every final child reap/group result before replaying
final samples. Once actual reader termination is confirmed, Root can restore
the same owned inode to 0400 even if raw adjudication failed. Failure of
adjudication still blocks external acceptance. If S was definitely never
started, restoration instead requires the same original boot, canonical inode
and root owner/group, a known command terminal, and a fresh 0444 check. A
failed post-open verification permits no blind restoration: unknown commands or
a changed identity require manual recovery. Restoration after any attempt to
start S always requires actual reader-termination evidence. Reader close is not
inferred from EOF, supervisor exit, a failed start or P group cleanup.

User dahlia remains the emergency restoration owner when Root or its channel
is lost. No automatic maximum exposure time is claimed. A nonzero `chmod` exit
status does not establish that the UUID file mode is unchanged. Changed
inode/boot/owner or unknown terminal requires manual recovery. 0400 does not
revoke UUID copies already read. The automatic T candidate is neither adopted
nor made a prerequisite here.

Root supplies original ingress controls for its explicit complete allocation,
separately for each fresh H request and purpose. Every allocated ingress must
cover the full original bounds, including an original observation through the
requested end; pending jobs, active hooks or children block admission. The
final external receipt binds the allocation, original reader-close evidence and
all command originals after restoration. Large private control payloads use
ordered, pinned parts beneath the unchanged 65,536-byte frame ceiling. For each
payload, the reader replays every original byte and the payload's aggregate
hash before returning the full proof. For partitioned payloads, the receipt
pins only the frames. Before waiting for the receipt and again after receiving
it, the operator replays the reader-close payload, its summary and raw
inventory, and every retained command original, decoding partitioned controls
through the original codec. A missing or changed part fails even when its frame
is unchanged. Internal H completion or *reader-closed.json* alone cannot
establish operating or publication success. This path adds no public origin,
signer, secret, token, OIDC claim or privilege.


Profiler replay and timing method
---------------------------------

`createKernelRootBoundaries()` maps H's fixed-count profile descriptor to P's
`existing-artifact` request. The base native timed command keeps empty `argv`
and its original 100-call correctness record. The profile uses the same
optimized, uninstrumented executable path, bytes and hash, environment, `cwd`
and `stdin`, with exactly one `--oseo-kernel-profile` argument. The adapter
independently requires 2000 calls for `sieve`, 1000 for `permute` and 10000
each for `json-roundtrip` and `regexp`. Startup, reference and observation forms
cannot supply profile evidence.

The request preserves factual `baseline100` `stdout` bytes. Those bytes are
not the profile oracle: P must use H's N-specific checker for both actual
preflight and target output. The checker ID includes `kernel-fixed-count-v1`,
the kernel and its fixed N; its actual source and declared source closure
remain pinned in P inputs. The child retains H's callback in process, and
replay requires the original caller-checker receipt. Exact baseline bytes
cannot substitute for missing checker evidence.

`replayKernelProfile()` reconstructs H's proof from original request/checker
receipts, saved input map and bytes, before/after source records, discovery
commands, profiler identity, preflight/target terminals, symbol observations
and eight separate useful raw captures. The proof hashes `profile.run`,
keeps the original N-call target output and status, and preserves the same
artifact ID and executable identity. Linux captures retain their original
GDB `argv`. Mac captures retain the same target PID, each 1s/10ms request, raw
report and complete window, including their permitted overlap. P's own group
cleanup remains separate from escaped-descendant adjudication.

H still owns 53 roles and eight timed artifacts, each with eight profile
captures. It also owns three warmups and 15 retained samples, 100 calls
inside each timing/RSS/observe kernel process, and 15 RSS launches. H retains
startup control roles, separate observation builds, the same timed hash and Mac
first-execution discard. Startup populations retain 3 warmups and 15 retained
samples; the program's control iteration is one. Profile and timing windows
remain separate on both native hosts. Fixed-count profiles diagnose a separate
workload on the same new binary; they do not decompose the original 100-call
timing or establish its direct call proportions. The fixed counts do not
guarantee sufficient target lifetime or successful capture. The demo's 54
combinations, 91 correctness cases, runtime C and profile-only enlarged-input A
are unchanged by this adapter.


Verification and operating prerequisites
----------------------------------------

Offline tests replay complete P originals, actual S parser/raw contracts,
private parent/child IPC, causal lifetime wires, stable ancestry and original
Mac command/listener transitions. They include source drift, partial open,
parent loss, early S terminal, detached P, reader-close and restore failures.
The fixtures use inert files and injected producer doubles; none launches a
workload, reads the live UUID or changes a service. They do not establish
actual operating permissions, physical exclusion or profiler acceptance.

Root must freeze the final diff and full static/dynamic/read-as-data closure,
complete normal three-stage and separate prose reviews, outer, normal commit,
D3/required Full, ordinary and applicable extended gates, CI and deployment
acceptance. The real new S's normal source acceptance and integrated H/P/S
end-to-end checks precede operating admission. Root then supplies actual
control originals and two-host profile/timing evidence. Whole-window acceptance
fails when operating evidence is missing or unknown.
